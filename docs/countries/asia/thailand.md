# เป็นธุรกิจที่พร้อมสำหรับเอเจนต์ AI ด้วย ABIZ ในประเทศไทย

*คู่มือสำหรับ ABIZ 1.1 (ข้อกำหนดที่เผยแพร่) [ข้อกำหนด (SPEC.md ภาษาอังกฤษ)](../../../SPEC.md) เป็นเอกสารหลัก หากคู่มือนี้กับข้อกำหนดไม่ตรงกัน ให้ถือตามข้อกำหนด*

## 1. ความหมายสำหรับธุรกิจในประเทศไทย

ทุกวันนี้ผู้ช่วย AI มักถูกถามว่า “เว็บไซต์จริงของบริษัทนี้คือเว็บไหน” หรือ “ใครเป็นผู้ดำเนินกิจการร้านนี้” ABIZ (Agentic Business Record) เป็นมาตรฐานเปิดที่ช่วยให้ธุรกิจในประเทศไทยเผยแพร่ข้อมูลสาธารณะของตนเพียงครั้งเดียวในรูปแบบที่เครื่องมือเหล่านี้อ่านได้ คือระเบียน DNS แบบ TXT สั้น ๆ บนโดเมนที่ธุรกิจควบคุม ซึ่งชี้ไปยังระเบียนธุรกิจรูปแบบ JSON ที่ให้บริการผ่าน HTTPS เนื่องจากตัวชี้อยู่ใน DNS ของธุรกิจเอง เครื่องมือจึงตรวจได้ว่าผู้ที่ควบคุมโดเมนนั้นเป็นผู้เผยแพร่ระเบียน แทนที่จะต้องพึ่งไดเรกทอรีที่ไม่เป็นทางการหรือการคาดเดา

## 2. วิธีเผยแพร่ระเบียน ABIZ

### ฟิลด์ที่ต้องมี

ระเบียนธุรกิจทุกรายการต้องมีห้าฟิลด์ต่อไปนี้ (SPEC หัวข้อ 4.1):

| ฟิลด์ | ตัวอย่างและกฎ |
|---|---|
| `record_version` | `abiz1` |
| `business_name` | ชื่อสาธารณะที่ลูกค้ารู้จัก เช่น `บริษัท ดอยคำ คอฟฟี่ จำกัด` |
| `country` | `th` รหัส ISO 3166-1 alpha-2 ตัวพิมพ์เล็ก |
| `identity_host` | `doikhamcoffee.th.to.co` ต้องตรงกับ `h` ใน DNS ทุกตัวอักษร |
| `domains` | `["doikhamcoffee.example"]` ต้องมีโดเมนที่ใช้ `_abiz` อยู่ด้วย |

### คีย์ธุรกิจ `k` (ไม่บังคับ)

`k` ไม่บังคับสำหรับทุกธุรกิจ ไม่ว่าจะจดทะเบียนหรือไม่ หากเผยแพร่ ค่าต้องเท่ากับ `business_key` ในระเบียน และระเบียนต้องมี `registration_number` ด้วย สำหรับประเทศไทย รูปแบบคือ:

```text
th-<registration-number>
```

ประเทศไทยไม่ใช้รหัสเขตการปกครอง อย่าใส่รหัสจังหวัดหรือเมือง SPEC หัวข้อ 4.2.2 กำหนดให้ใช้รหัสเขตย่อยเฉพาะสหรัฐอเมริกา บริษัทระดับมณฑลของแคนาดา และสหรัฐอาหรับเอมิเรตส์ และห้ามใช้ในประเทศอื่นทั้งหมด

**หมายเลขที่ใช้:** เลขทะเบียนนิติบุคคล 13 หลัก ซึ่งเป็นเลขประจำตัวผู้เสียภาษีอากรของนิติบุคคลด้วย

**การทำให้เป็นมาตรฐาน (SPEC หัวข้อ 4.2.3):** เริ่มจากหมายเลขตามที่นายทะเบียนออกให้ ใช้การทำ Unicode NFKC ลบช่องว่าง `-` `.` `/` และขีดต่าง ๆ แล้วเปลี่ยนตัวอักษรละตินเป็นตัวพิมพ์ใหญ่ เก็บเลขศูนย์นำหน้าและอักษรนำหน้าไว้ ผลลัพธ์ต้องมีเฉพาะตัวอักษรและตัวเลข ASCII หากไม่ใช่ จะเผยแพร่คีย์ธุรกิจไม่ได้ ให้ละ `k` `business_key` และ `registration_number`

**ตัวอย่าง (สมมุติ):** `0105565123456` กลายเป็น `0105565123456` จึงได้ `k=th-0105565123456` ในระเบียนเขียนว่า `"business_key": "th-0105565123456"` และ `"registration_number": "0105565123456"` การเปรียบเทียบคีย์ไม่แยกตัวพิมพ์ใหญ่เล็ก รูปแบบมาตรฐานคือรหัสประเทศตัวพิมพ์เล็กและหมายเลขตัวพิมพ์ใหญ่

**ตัวเลขไทย:** NFKC ไม่แปลงตัวเลขอย่าง ๑๒๓ เป็น 0–9 หากหมายเลขของคุณเขียนด้วยเลขไทยเท่านั้น ผลลัพธ์จะไม่ใช่ ASCII และใช้เป็นคีย์ไม่ได้ ABIZ 1.1 ไม่ได้กำหนดการแปลงตัวเลข ให้ใช้หมายเลขในรูปเลขอารบิก 0–9 ตามที่นายทะเบียนออกให้

**ผู้ประกอบการบุคคลธรรมดา:** หากหมายเลขเดียวที่คุณมีเป็นหมายเลขส่วนบุคคล เช่น เลขประจำตัวประชาชน อย่าเผยแพร่ `k` ให้ละ `k` `business_key` และ `registration_number` ระเบียนยังคงถูกต้อง

### ระเบียน DNS แบบ TXT

เผยแพร่ระเบียน TXT เพียงรายการเดียวที่ชื่อ `_abiz` ใต้โดเมนของคุณ ในรูปแบบกะทัดรัดไม่มีช่องว่าง โดยมี `v=abiz1` อยู่ก่อน:

```dns
_abiz.doikhamcoffee.example. 300 IN TXT "v=abiz1;k=th-0105565123456;h=doikhamcoffee.th.to.co;p=cwODo5gwp0fpMqSYTYfT+B9fj0rmIrjiq6d64tR4mhI="
```

ค่า `p` ข้างต้นเป็นกุญแจตัวอย่างแบบใช้ครั้งเดียวที่สร้างขึ้นสำหรับหน้านี้ ห้ามคัดลอกไปใช้ ให้เผยแพร่กุญแจของคุณเองการประกาศ ABIZ 1.1 ต้องมี `p` ชื่อ หมายเลข และโดเมนทั้งหมดในหน้านี้เป็นข้อมูลสมมุติ

หากไม่ใส่แท็ก `k` ซึ่งไม่บังคับ ค่านี้ก็ใช้ได้เช่นกัน:

```dns
_abiz.doikhamcoffee.example. 300 IN TXT "v=abiz1;h=doikhamcoffee.th.to.co;p=cwODo5gwp0fpMqSYTYfT+B9fj0rmIrjiq6d64tR4mhI="
```

ระเบียนธุรกิจที่ให้บริการเป็น `application/json` ที่ `https://doikhamcoffee.th.to.co`:

```json
{
  "record_version": "abiz1",
  "business_name": "บริษัท ดอยคำ คอฟฟี่ จำกัด",
  "country": "th",
  "business_key": "th-0105565123456",
  "registration_number": "0105565123456",
  "identity_host": "doikhamcoffee.th.to.co",
  "domains": [
    "doikhamcoffee.example"
  ],
  "public_key": "cwODo5gwp0fpMqSYTYfT+B9fj0rmIrjiq6d64tR4mhI=",
  "signature": "2IrgXW6Tt0wx2tZCBJpDep5ayEWrEG3pLaBk9xsNBoqGZ62B7MKBbnTdy6jaTv3BCB605b6s47ioj2MDFJIOBw=="
}
```

หากต้องการตรวจระเบียนก่อนเผยแพร่ ให้รันตัวตรวจสอบอ้างอิงจากสำเนาของรีโพซิทอรีนี้:

```sh
python scripts/validate.py record.json --domain doikhamcoffee.example --dns-value 'v=abiz1;k=th-0105565123456;h=doikhamcoffee.th.to.co;p=cwODo5gwp0fpMqSYTYfT+B9fj0rmIrjiq6d64tR4mhI='
```

คุณจะโฮสต์ระเบียน JSON เองบนเซิร์ฟเวอร์ HTTPS ใดก็ได้ หรือใช้ผู้ให้บริการที่รองรับรายใดก็ได้ ABIZ ไม่บังคับผู้ให้บริการรายใดรายหนึ่ง

## 3. การใช้ผู้ให้บริการและ MCP

Model Context Protocol (MCP) เป็นโปรโตคอลเปิดที่ให้ผู้ช่วย AI เรียกใช้เครื่องมือและอ่านข้อมูลจากเซิร์ฟเวอร์ภายนอกด้วยวิธีมาตรฐาน ระเบียนธุรกิจอาจมีฟิลด์ `mcp_server_url` (ไม่บังคับ) ซึ่งเป็นที่อยู่ HTTPS ของเซิร์ฟเวอร์ MCP ของธุรกิจ เช่น สำหรับการจองหรือข้อมูลสินค้า ABIZ ไม่รับรองเซิร์ฟเวอร์นั้น เครื่องมือต้องใช้การควบคุมการเข้าถึงของตนเอง (SPEC หัวข้อ 4.2.6)

ผู้ให้บริการสามารถโฮสต์ระเบียนและเผยแพร่ตัวชี้ DNS แทนคุณได้ ตัวอย่างเช่น บริษัทที่จดทะเบียนในประเทศไทยและโฮสต์ระเบียนกับ to.co อาจใช้โฮสต์ `doikhamcoffee.th.to.co` ซึ่งได้ค่า DNS เป็น `v=abiz1;k=th-0105565123456;h=doikhamcoffee.th.to.co;p=cwODo5gwp0fpMqSYTYfT+B9fj0rmIrjiq6d64tR4mhI=` ส่วนธุรกิจที่ไม่ได้จดทะเบียนอาจใช้โฮสต์ที่มีชื่อเมือง เช่น `doikhamcoffee-chiangmai.biz.to.co` ผู้ให้บริการที่รองรับรายอื่นหรือเซิร์ฟเวอร์ของคุณเองก็ทำงานแบบเดียวกัน

## 4. คีย์และลายเซ็น (ABIZ 1.1)

ABIZ 1.1 กำหนดให้มีคีย์สำหรับลงนาม แท็ก DNS `p` บรรจุกุญแจสาธารณะ Ed25519: 32 ไบต์ดิบ, base64 มาตรฐาน, 44 อักขระ, `=` ท้ายหนึ่งตัว (SPEC หัวข้อ 3.3.2) ไม่รับ base64url ธุรกิจหรือผู้ให้บริการที่ทำการแทนจะเก็บกุญแจส่วนตัวที่คู่กัน และใช้ลงนามระเบียนธุรกิจ กุญแจส่วนตัวเป็นของธุรกิจเสมอ และผู้ให้บริการโฮสต์ต้องให้ธุรกิจส่งออกกุญแจได้

- `v` และ `h` เป็นข้อบังคับ `p` เป็นข้อบังคับ `k` ไม่บังคับ `p` ต้องเป็นกุญแจที่ถูกต้อง ค่าอื่นใด เช่น สตริงเลขฐานสิบหกหรือกุญแจแบบ base64url จะทำให้การประกาศทั้งหมดไม่ถูกต้อง
- เผยแพร่เฉพาะกุญแจปัจจุบัน หากจะหมุน กุญแจ ให้สร้างคู่กุญแจ Ed25519 ใหม่ เผยแพร่กุญแจสาธารณะใหม่ในการประกาศ DNS หรือ well-known ลงนามระเบียนใหม่ด้วยกุญแจส่วนตัวใหม่ และตั้ง `public_key` ให้ตรงกับ `p` นั้น เผื่อเวลาแคช DNS การลบเฉพาะ `p` ไม่ใช่การเพิกถอนที่ถูกต้องตราบใดที่การประกาศ ABIZ 1.1 ยังอยู่: หากจะถอน ให้ลบการประกาศ DNS หรือ well-known ทั้งชุด ใน ABIZ 1.1 ไม่มีการเผยแพร่กุญแจที่เลิกใช้แล้ว ทั้งใน DNS และในระเบียนธุรกิจ
- กุญแจแสดงว่าใครควบคุม DNS ของโดเมน แต่ไม่ได้พิสูจน์ตัวตนตามกฎหมาย

## 5. สิ่งที่เครื่องมือ AI จะเห็น

เครื่องมือที่รองรับซึ่งอ่านระเบียนของคุณสามารถตอบคำถามเช่น:

1. เว็บไซต์ทางการของ บริษัท ดอยคำ คอฟฟี่ จำกัด คือเว็บไหน
2. โดเมนใดบ้างที่เป็นของธุรกิจนี้
3. ธุรกิจนี้ระบุเลขทะเบียนอะไร และในประเทศใด
4. ให้บริการอะไร และเปิดทำการเมื่อไร

**ข้อจำกัด:** ABIZ แสดงสิ่งที่ผู้ควบคุมโดเมนเผยแพร่ ไม่ได้พิสูจน์ว่าธุรกิจจดทะเบียนถูกต้องตามกฎหมาย ว่าหมายเลขเป็นของจริง หรือว่าบริการ AI หน่วยงานรัฐ หรือผู้ให้บริการใดรับรองธุรกิจนั้น ในกรณีที่สำคัญ เครื่องมือและผู้ใช้ควรตรวจสอบกับทะเบียนทางการ

## 6. หมายเหตุเชิงปฏิบัติในประเทศ

- **ทะเบียน:** กรมพัฒนาธุรกิจการค้า กระทรวงพาณิชย์ เว็บไซต์ทางการ: <https://www.dbd.go.th>.
- **การเพิ่มระเบียน TXT:** ในการตั้งค่า DNS ของผู้รับจดโดเมนหรือผู้ให้บริการ DNS ให้เพิ่มระเบียน TXT ชื่อ `_abiz` (บางแผงควบคุมต้องใส่ชื่อเต็ม เช่น `_abiz.yourdomain.co.th`) ใส่ค่าข้างต้น และตั้ง TTL เป็น 300 วินาที โดเมน `.co.th` ใช้งานเหมือน `.com` หรือโดเมนอื่น พยายามอย่าแยกค่า และห้ามแยก `p`
- **ข้อมูลส่วนบุคคล:** พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) ระเบียน ABIZ เป็นข้อมูลสาธารณะ ให้เผยแพร่เฉพาะข้อมูลธุรกิจที่คุณยินดีเปิดเผย และอย่าใส่ที่อยู่บ้านหรือหมายเลขโทรศัพท์ส่วนตัว (SPEC หัวข้อ 4.3)
